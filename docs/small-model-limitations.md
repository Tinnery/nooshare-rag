# 小模型限制与已知问题

## 概述

本文档记录 nooshare-rag MVP 中使用小模型（qwen3-embedding:0.6b）的已知限制和问题。

## 1. Embedding 模型限制

### 1.1 数字精确匹配失败

**问题**：0.6B 参数的 embedding 模型无法精确匹配数字。

**表现**：
- 查询「平安银行2024年净利润」时，包含「445.08」的 chunk 向量相似度仅 0.61-0.66
- 查询「贵州茅台2023年营业收入」时，包含「147,693,604,994.14」的 chunk 无法通过向量检索找到

**原因**：
- 小模型的 embedding 空间对数字的编码不够精细
- 数字在文本中的语义权重被稀释
- 缺乏对财务数字的专门训练

**缓解方案**：
- 依赖 FTS（全文检索）进行数字匹配（已采用，FTS 权重 0.7）
- 考虑使用更大的 embedding 模型（如 bge-large-zh-v1.5，1024 维）
- 在 chunk 中显式标注关键数字（待实现）

### 1.2 语义理解有限

**问题**：小模型对复杂财务概念的理解有限。

**表现**：
- 「每股收益」与「EPS」的语义关联较弱
- 无法准确理解「分红」「股利」「派息」的同义关系

**缓解方案**：
- 使用同义词扩展查询
- 依赖 FTS 的精确匹配
- 考虑使用更大的模型或微调

## 2. FTS 分词问题

### 2.1 jieba 分词与公司名缺失

**问题**：chunk 来自财务报表部分，可能不包含公司名称。

**表现**：
- 查询「贵州茅台2023年基本每股收益」时，jieba 分词为「贵州 & 茅台 & 2023 & 年 & 基本 & 每股 & 收益」
- 包含「基本每股收益」的 chunk 不含「贵州」「茅台」，导致 AND 匹配失败

**缓解方案**：
- 在 chunk 预处理时添加公司名/股票代码前缀（待实现）
- 使用 OR 逻辑替代 AND（会降低精确度）
- 在 document metadata 中存储公司名，查询时动态添加

### 2.2 数字格式不匹配

**问题**：年报中的数字格式多样，查询时难以预测。

**表现**：
- 年报中可能是「147,693,604,994.14」（元）或「1,476.94」（亿元）
- 查询时无法确定用户期望的格式

**缓解方案**：
- 在 ground truth 中使用年报中的实际格式
- 考虑在索引时标准化数字格式（待实现）

## 3. 检索策略

### 3.1 Hybrid Search 权重调整

**当前配置**：
- FTS 权重：0.7
- Vector 权重：0.3
- RRF k=60

**原因**：
- 小模型的 vector 无法精确匹配数字，需要依赖 FTS
- FTS 的精确匹配对财务数据检索更重要

**RRF Score 说明**：
- RRF 公式：weight / (k + rank + 1)
- 最大 score 约等于 0.016（k=60 时）
- 这是正常特性，非 bug

### 3.2 Chunk 大小优化

**当前配置**：
- max_chunk_size=2000
- overlap=300

**效果**：
- 从 2060 chunks 降至 799 chunks
- 更大的 chunk 包含更多上下文，有利于 FTS 匹配

## 4. 测试用例修正记录

### 4.1 Test 3: 贵州茅台2023年营业收入

**原始 ground truth**：1,476.94
**修正后**：147,693,604,994.14

**原因**：年报中实际数字是 147,693,604,994.14 元（约 1,476.94 亿元），测试用例应使用年报中的实际格式。

### 4.2 Test 4: 贵州茅台2023年基本每股收益

**问题**：FTS 返回 0 结果
**原因**：jieba 分词 AND 逻辑 + chunk 不含公司名
**状态**：待修复

## 5. 后续改进方向

1. **升级 embedding 模型**：考虑使用 bge-large-zh-v1.5 或更大的模型
2. **Chunk 元数据增强**：在每个 chunk 前添加公司名/股票代码
3. **数字标准化**：在索引时统一数字格式
4. **同义词扩展**：在查询时扩展同义词
5. **混合检索优化**：探索更复杂的检索策略（如先 FTS 后 vector rerank）
